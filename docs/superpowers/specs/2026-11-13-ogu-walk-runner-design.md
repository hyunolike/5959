# 오구의 마음 산책 — 서버 대기 게임 재설계

상태: 사용자 승인 후 산책 러너로 교체 완료. 로컬 구현과 검증 완료, 배포 전.

## 의도

사용자가 크롬 오프라인 공룡 게임처럼 단순하고 반복해서 즐길 수 있는 게임으로 재설계를 요청했다. 현재 방울 모으기는 고정된 버튼을 반복해서 누르는 방식이고 타이밍 학습, 위험과 보상, 기록 재도전이 약하다. 새 게임은 한 번의 조작으로 이해하고 여러 번 도전하는 러너로 설계한다.

오구와 작은 감정 몬스터가 함께 산책한다. 돌부리를 점프로 넘으며 가능한 멀리 함께 간다. 몬스터는 동료이고 장애물은 길 위의 사물이다. 서비스의 감정 표현을 이용해 사용자를 평가하거나 감정이 개선됐다고 판정하지 않는다.

## 접근 비교와 선택

- 한 버튼 러너(추천): 익숙한 점프와 장애물만으로 즉시 이해하고 타이밍을 익힐 수 있다. 캐릭터의 관계와 움직임으로 오구오구의 분위기를 담는다.
- 떨어지는 하트 받기: 응원이라는 주제는 맞지만 좌우 이동과 모바일 조작을 따로 설명해야 한다.
- 박자에 맞춰 응원하기: 서비스 행동과 연결되지만 음소거 환경에서 박자를 전달하기 어렵고 별도의 리듬 학습이 필요하다.

사용자가 가장 어울리는 방향의 선정을 맡겼으므로 러너를 제안한다. 공룡의 그래픽이나 코드를 복제하지 않는다. 참고한 원칙은 단순한 조작과 반복 가능한 기본 동작이다.

## 게임 규칙

1. 대기 안내 아래 높이 약 220px의 가로 무대를 둔다. 시작 전에는 정지한 오구와 동료, `톡 눌러 함께 산책하기`를 보인다. 자동 플레이하지 않는다.
2. 무대를 누르거나 무대에 초점이 있을 때 Space/↑를 누르면 시작과 점프를 한다. 한 번 누르면 일정한 높이로 한 번 뛰며 공중에서 다시 뛰지 않는다. 길게 누름과 키 반복으로 자동 점프하지 않는다.
3. 캐릭터는 왼쪽에 있고 길과 장애물이 오른쪽에서 왼쪽으로 움직인다. 동료는 오구의 점프를 따라가는 연출이며 충돌 판정은 오구 하나에만 적용한다.
4. 처음 5초는 장애물이 없는 연습 구간이다. 이후 낮은 돌부리, 낮은 나무토막을 하나씩 소개한다. 공중 장애물과 숙이기, 아이템과 별도 자원은 첫 버전에서 제외한다.
5. 15초마다 조금 빨라지고 60초 이후에는 속도를 유지한다. 화면 폭에 맞춰 속도와 장애물 배치를 조정해 320px에서도 등장 후 최소 1.2초의 반응 시간을 준다. 모든 장애물은 한 번의 점프로 통과 가능해야 하며 착지 후 다음 점프를 준비할 간격을 보장한다. 값은 초기 제안이며 실제 플레이 후 조정한다.
6. 점수는 함께 이동한 거리 하나다. 무대 위에 `함께 128m`, `이번 방문 최고 246m`처럼 표시한다. 하트, 콤보, 체력, 순위, 업적은 추가하지 않는다.
7. 충돌하면 해당 판을 끝낸다. 캐릭터는 잠깐 주저앉고 동료가 곁에 멈춘다. `잠깐 쉬어 가요`와 이동 거리를 보여 준다. 짧은 입력 잠금 뒤 같은 조작 또는 `다시 산책하기`로 재시작한다. 실수와 재도전은 유지하되 죽음이나 비난 연출은 쓰지 않는다.
8. 25초 고정 종료를 없앤다. 충돌하거나 서버가 준비될 때까지 이어 간다. 서버 대기 시간이 긴 경우에도 여러 판을 자연스럽게 반복할 수 있다.
9. 낮 20초, 해질녘 4초, 밤 20초, 새벽 4초로 하늘이 반복된다. 진행 중인 한 판의 시간만 사용하며 정지/충돌 시 하늘도 멈춘다. 재시작하면 낮이다. 밤에는 달과 고정된 별이 보이고 길과 초점은 밝아진다. 안내는 밝은 면에 놓는다. 움직임 줄이기는 중간 색 없이 전환한다.

## 서버 대기와 연결

- 상단의 서버 상태와 예상 대기 안내는 계속 보인다. 게임 거리와 서버 준비율은 연결하지 않는다.
- 준비 완료 시 장애물과 충돌 판정을 즉시 멈추고, 점프 중이라면 짧게 착지시킨다. `준비됐어요. 이제 마음 이야기를 나눠요.`를 보이고 최대 1.2초 이내 기존 화면으로 복귀한다. 즉시 계속하기도 제공한다.
- 이미 제출한 로그인과 가입은 기존 자동 제출을 유지한다. 게임 조작이 폼을 제출하거나 제출을 지연하지 않는다.
- 탭이 숨겨지거나 게임에서 초점이 벗어나면 일시정지한다. 돌아오면 `이어서 산책하기`를 눌러 재개한다. 숨겨진 동안 이동 거리와 충돌을 계산하지 않는다. 서버 준비 확인은 기존 흐름을 따른다.
- 연결 실패 시 놀이를 중단하고 기존 재연결 동작을 제공한다. 재연결 확인이 시작되면 이전 판은 종료한 상태로 정리한다.
- 게임을 접으면 대기 안내와 입력 화면으로 돌아간다. 닫기 버튼은 무대 밖에 두어 점프 입력과 구분한다.

## 화면과 자산

- 기존 Pretendard, 역할 색, 둥근 면, 공용 Button과 초점 표시를 사용한다. 기존 대기 안내와 무대를 합쳐도 로그인 화면을 덮는 모달로 만들지 않는다.
- 흰색과 중립 선으로 길을 간결하게 표현한다. 오구와 동료에만 기존 일러스트의 색과 질감을 유지한다. 감정 색은 해당 감정 몬스터를 표현할 때만 사용한다.
- 오구는 옆모습의 달리기 4프레임, 점프, 쉬기 프레임을 준비한다. 동료와 장애물도 같은 그림체의 자산을 사용한다. 프레임에는 동일한 기준점과 투명 여백을 맞춘다.
- 게임 중에는 설명과 큰 캐릭터 정면 이미지를 반복해서 쌓지 않는다. 핵심은 가로 무대 하나, 거리, 짧은 조작 안내다.

## 접근성과 구현 경계

- 키보드 입력은 무대가 초점을 가진 동안만 처리한다. 로그인 입력 중 Space나 ↑를 가로채지 않는다. 시작, 일시정지, 재시작, 닫기는 이름이 있는 실제 버튼으로 제공한다.
- 움직임 줄이기를 선택한 사람에게 자동 스크롤을 시작하지 않는다. 동작 설명 후 직접 시작할 수 있게 하며, 배경의 장식 움직임, 화면 흔들기, 확대와 축소를 제거한다. 게임을 열지 않고 기다릴 선택을 항상 유지한다.
- 점수를 매 프레임 낭독하지 않는다. 준비 완료와 판 종료만 별도의 안정된 상태 영역으로 알린다. 소리는 기본으로 사용하지 않는다.
- 바깥 UI는 기존 React와 Framer Motion을 재사용한다. 게임 시뮬레이션과 그리기는 Canvas 2D + requestAnimationFrame으로 분리한다. React 상태를 매 프레임 갱신하지 않는다. 이 범위에서는 별도 게임 엔진을 추가하지 않는다.
- 서버 요청과 계정 저장은 없다. 방문 중 최고 기록은 sessionStorage가 사용 가능할 때만 저장하고 실패하면 메모리로 계속 동작한다. 실제 레이드 HP, 공감 수, 도감과 연동하지 않는다.

## 검증 기준

- 별도의 설명 없이 첫 점프와 재시작을 이해하는지 실제 플레이로 확인한다.
- 평균 한 판 20~60초를 초기 목표로 삼고 모바일과 데스크톱의 반응 시간과 실패 빈도를 비교한다. 아직 측정된 결과는 아니다.
- 프레임 속도 차이와 복귀 후 긴 프레임이 이동 거리, 점프 높이, 충돌 결과를 바꾸지 않는지 확인한다.
- 320px에서 장애물과 문구를 읽을 수 있고, 점프 가능한 패턴만 생성되는지 확인한다.
- 게임 중 준비 완료, 점프 중 준비 완료, 실패 후 재연결, 로그인 자동 제출, 초점 이동과 움직임 줄이기 설정을 검증한다.
- 성공 판단은 오래 플레이한 시간보다 대기 진입 후 원래 작업으로 도달한 비율과 준비 완료 뒤 복귀 시간으로 한다.
