# 오구오구(5959) Claude Code 원본 구현 보고

이하 내용은 제한된 파일 도구로 실행한 Claude Code의 원본 보고다. 여기서 “테스트를 실행하지 않았다”는 문장은 Claude CLI 단계에만 해당한다. 이후 코디네이터가 실제 통합·회귀 테스트·렌더 검증을 수행했다. 최종 결과는 이 문서 아래의 통합 검증에 기록한다.

기존 UI 파일 22개를 수정했고 새 소스 파일은 없습니다. **렌더, 타입 검사, 린트, 기능 테스트는 실행하지 않았습니다**(파일 도구만 사용). 아래 변경은 모두 코드 읽기에 근거한 것이며 실제 화면으로 확인하지 못했습니다.

## (a) 우선순위와 화면별 변경 이유

### 우선순위

1. **화면마다 primary action을 하나로** — 채운 보라 버튼이 한 화면에 여러 개이거나, 선택 상태가 primary 버튼과 같은 모양이던 곳을 정리했습니다.
2. **읽기 순서를 목록 → 본문 → 공감/댓글로** — 상세에서 몬스터가 본문보다 먼저 나오던 순서를 바꾸고, 카드 3장을 읽기 면 2개로 줄였습니다.
3. **익명 방문자가 무엇을 볼 수 있고 무엇이 잠겨 있는지** — 익명 홈 소개와 탐색의 잠금 표시.
4. **빈 상태, 오류, 로딩이 같은 자리와 같은 면에서** — 끝나지 않는 스피너 1건 수정 포함.
5. **보라는 primary action과 현재 위치에만** — 목록 hover, 필터 칩 hover, 탐색 hover를 중립색으로.

### 화면별

| 화면 | primary action | 문제 | 변경 |
| --- | --- | --- | --- |
| 익명 `/home` | 로그인하고 이야기 보기 | primary 버튼 2개가 경쟁. 소개가 한 문단. 마지막 문장이 "메뉴를 살펴보라"고만 함 | `고민 쓰기`를 outline으로 낮춤. 사용 순서 3단계와 메뉴 4개 설명을 추가. `/signup` 링크 추가 |
| 탐색(사이드/하단) | 현재 위치 확인 | 익명에게 잠긴 메뉴와 열린 메뉴가 같아 보임. 모바일에서 선택(채운 보라)과 이동 대기(연보라)가 둘 다 채움 | 잠긴 메뉴에 작은 자물쇠와 `aria-describedby` 설명. 선택은 연보라 채움+점+굵은 글씨, 대기는 채움 없이 스피너+"이동 중" |

| 작성 `/write` | 올리기 | 선택된 말투가 primary 채움이라 `올리기`와 경쟁. 말투가 무엇에 쓰이는지 설명 없음. 장식 아이콘 타일 | 선택은 연보라 면+체크, 채운 보라는 `올리기`만. 고민/말투 두 질문에 각각 한 줄 설명. 제출 중 스피너 아이콘과 `aria-busy`. 아이콘 타일 제거 |

| 레이드/알림/주간 리포트 | 변경 없음 | 제목 크기 불일치 | 제목을 `text-2xl font-bold`로 통일. 레이드는 제목 위에 탐색 라벨 표기 |

### 판단이 어려워 보존한 것

- **화면 제목 문구**(`레이드`, `마이페이지`, `이메일로 가입하기`)와 `피드로` 링크: 탐색 라벨(`함께 이겨내기`, `내 마음 기록`, `마음 이야기`)과 다르고, `이메일로 가입하기`는 소셜 버튼이 있는 화면의 제목으로 맞지 않습니다. 다만 제목과 링크 이름을 찾는 테스트가 있을 수 있어 문구는 그대로 두고 탐색 라벨을 작게 병기했습니다. 테스트에 걸리지 않는다면 제목을 탐색 라벨로, `이메일로 가입하기`를 `회원가입`으로, `피드로`를 `마음 이야기`로 바꾸길 권합니다.
- **회원 홈의 로그아웃 버튼**: `고민 쓰기` 옆에 있어 primary와 경쟁하지만, 로그아웃 흐름 보존 지시에 따라 위치를 유지했습니다. `/my`에도 있으므로 홈에서는 빼는 것을 권합니다.
- **글 불러오기 실패의 재시도 버튼**: `usePostDetailQuery`가 `refetch`를 돌려주는지 이 영역에서 확인할 수 없어 `마음 이야기로 돌아가기` 링크만 두었습니다.
- **피드 카드의 몬스터**: 장식이 아니라 글의 실제 감정 데이터라 유지했습니다. `MonsterDisplay` 소스가 없어 크기는 건드리지 못했습니다.
- **`분석 중`, 제출 버튼 라벨, 모든 `aria-label`**: 그대로입니다.

## (b) 참고한 패턴과 복제하지 않은 것

이 세션에는 웹 접근 도구가 없어 **다섯 참고 자료를 직접 열어 보지 못했습니다.** 요청에 적힌 설명만 방향으로 삼았고, 코드·이미지·문구는 가져오지 않았습니다.

| 참고 | 적용한 것 | 하지 않은 것 |
| --- | --- | --- |
| 보투게더 | 탐색은 열어 두고 참여 시점에 인증을 요구하는 구분. 잠긴 메뉴를 미리 표시 | 익명에게 글을 보여 주지 않음(공개 API 없음). `window.alert` 없이 기존 sheet 유지 |
| 리뷰미 | 흰 읽기 면, 짧은 미리보기, 질문-설명-입력의 계층과 여백 | 설문 단계, 날짜 UI |
| Layer | 작성 화면에서 질문 두 개(고민, 댓글 말투)를 각각 제목+한 줄 설명으로 분리 | 단계 분할, 임시저장, 추천, 완료 화면. 자유 입력 한 화면 유지 |
| GAMSS | 오구를 익명 안내, 빈 상태, 오류에만 사용 | 화면을 확인하지 못했으므로 시각적 근거로 삼지 않음 |
| Discourse | 목록 → 본문 → 공감/댓글 순서 | 카테고리, 태그, 신뢰 등급 등 |

새 캐릭터, 로고, 일러스트, 외부 이미지, 폰트는 없습니다. 이미지는 기존 `/brand/ogu-companion.png`만 씁니다.

## (c) 수정한 파일과 유지한 계약

수정 파일 목록은 `EDITED-FILES.json`과 같습니다(22개). 새 의존성은 없고, 아이콘은 기존 `lucide-react`의 `Lock`, `Check`, `LoaderCircle`, `ChevronLeft`만 추가로 불러옵니다.

**수정하지 않은 파일**: `guest-access-provider.tsx`, `confirm-dialog.tsx`, `button.tsx`, `card.tsx`, `input.tsx`, `label.tsx`, `list-skeleton.tsx`, `selection-indicator.tsx`, `spinner.tsx`, `brand-mark.tsx`, `globals.css`, `write-form.tsx`.

**유지한 계약**

- **AppShell**: `authenticated`/`showNavigation` 판단, 알림 조건, `NAVIGATION`의 href와 라벨, `guestNavigation`(prefetch false, `preventDefault`, `requestLogin(href)`), `current` 계산은 그대로입니다. 바뀐 것은 `NavigationItem`에 넘기는 표시용 `locked` prop 한 줄씩(사이드/하단)입니다.
- **NavigationItem**: `aria-label`, `aria-current`, `data-navigation-pending`, `data-current-mark`, `aria-busy`, `aria-live` 안내는 그대로입니다. 접근성 이름은 바뀌지 않고 잠금은 설명으로만 추가됩니다.
- **GuestHome**: 회원 API 호출 없음. `requestLogin("/home")`, `requestLogin("/write")`와 두 버튼의 이름 유지. 가짜 글, 회원, 수치, 랭킹, 공지, 검색 없음. 추가한 소개 문구는 코드에서 확인되는 동작(몬스터 생성, 공감/댓글로 HP 감소, 보스 레이드, 감정 통계)만 적었습니다.
- **데이터**: `useMeQuery`, `useFeedQuery`, `usePostDetailQuery`, `useCommentsQuery`, `useSimilarPostsQuery`, 변이, 쿼리 키, 무효화, 필터의 URL 동기화, 무한 스크롤은 손대지 않았습니다. `/my`에서 `useMeQuery`의 `isError`를 추가로 읽습니다(회원 홈에서 이미 쓰는 필드).
- **폼**: 제출 라벨(`올리기`, `저장`), `취소`, 필드 라벨(`고민`, `닉네임`, `직군`, `경력`), legend `댓글 말투`, `aria-pressed`, 스키마, 오류 처리 유지.
- **접근성**: 추가한 링크와 버튼은 모두 44px 이상(`답글 달기`, 로그인/가입 하단 링크를 44px로 올림). 스피너는 `motion-safe`에서만 회전. 하단 탐색의 safe area 처리 유지.

**테스트에 영향을 줄 수 있는 변경**(통합 시 확인 필요)

- 익명 홈의 마지막 안내 문장과 부제 문구가 바뀌었고 `회원가입` 링크가 생겼습니다.
- 글 상세에 `/home` 링크 2종(`마음 이야기`, `마음 이야기로 돌아가기`)과 제목 `이 고민에 달린 댓글`이 생겼고, `몬스터` 영역과 `댓글 말투`의 DOM 위치가 바뀌었습니다.
- 고민 입력란에 `aria-describedby`가 항상 붙습니다(오류 시 `content-error content-hint`).
- 닉네임 입력란에 `aria-describedby`와 `최대 10자` 문구가 생겼습니다.
- 회원 홈의 Suspense fallback이 `Spinner`에서 `ListSkeleton`으로 바뀌었습니다.
- 가입 화면에 `먼저 둘러보기` 링크, 가입 부제 문구 변경.

## (d) 남는 불확실성과 검증 제안

- **`cn`이 tailwind-merge를 쓴다고 가정했습니다.** `Card`/`Label`/`Button`에 넘긴 여백·글자 크기 덮어쓰기(`px-5 py-7`, `text-base font-bold`, `h-auto px-2 py-2 whitespace-normal`)가 이 가정에 의존합니다. clsx만 쓴다면 해당 클래스가 기대대로 적용되지 않을 수 있습니다.
- **Tailwind 4 임의 변형**(`[&>li:last-child>a]:border-b-0`, `[&>li]:py-4`)을 목록 마지막 줄 처리에 썼습니다. `PostCard`의 최상위가 `a`라는 구조에 의존합니다.
- **`MonsterDisplay`의 `detail`/`card` 크기를 모릅니다.** 상세에서 본문 아래로 옮긴 뒤 높이가 과하지 않은지, 공감 시 반응이 화면 안에 보이는지 확인이 필요합니다.
- **`CommentItem` 내부를 모릅니다.** `답글 달기`를 44px로 올리면서 같은 줄의 다른 버튼과 높이가 어긋날 수 있습니다.
- **말투 버튼**은 320px에서 긴 라벨이 줄바꿈되도록 했습니다. 실제 라벨 4개로 2열이 고르게 보이는지 확인이 필요합니다.
- **프로필 수정 부제**("닉네임, 직군, 경력은 내가 쓴 글에 함께 보여요")와 **작성 안내**("회원에게만 보여요")는 피드 카드와 회원 전용 API 계약에서 읽은 내용입니다. 제품 정책 문구로 맞는지 확인해 주세요.
- **검증 제안**: 타입 검사와 린트 → 기존 단위/E2E 테스트 → 320/390/1280 폭에서 익명 홈, 로그인, 피드(로딩/빈/오류/목록), 작성(미선택/선택/제출 중), 상세(내 글/남의 글/분석 중/없는 글), `/my`(조회 실패 포함), `/my/edit`(변경 없음/변경 있음) 확인 → 익명 탐색에서 잠긴 메뉴 3개가 sheet를 열고 취소·뒤로 가기 시 홈에 남는지, 스크린리더가 "로그인 후 이용할 수 있어요"를 설명으로 읽는지 확인 → 움직임 줄이기에서 스피너와 탐색 전환이 멈추는지 확인.


## 코디네이터의 통합 검증

공식 CLI 결과의 수정 선언과 실제 변경 파일 22개를 비교하고, 전달 당시 SHA-256과 로컬 대상 파일을 대조한 뒤 통합했다. 기존 익명 인증 흐름과 공용 대화상자 구현은 별도로 유지했다. `cn`은 실제로 tailwind-merge를 사용한다. 320/390/1440px 실제 API 화면을 렌더해 본문 우선순위, 입력/선택/저장 이유와 탐색을 확인했다. 320px 말투 라벨은 단어를 보존하도록 `break-keep`으로 보완했다.

리뷰에서 같은 오래된 history marker를 두 닫힌 대화상자가 정리하며 뒤로가기를 두 번 호출하는 문제를 재현했다. 실패 테스트를 먼저 추가하고 marker+URL 단위로 대기 중 정리를 합쳤다. 실제 설치/게스트 provider 구성은 뒤로가기 한 번, Chromium은 홈 유지로 재검증됐다.

- 단위 테스트: 105 파일 / 1,028개 통과.
- 일반 브라우저: 31개 통과(익명 흐름, 반복 클릭, history, 설치 안내, 키보드·모바일·오류 복구 포함).
- production build, 타입 검사, FSD: 통과. lint 오류 0; 변경하지 않은 `query-client.ts`의 기존 경고 1개 유지.
