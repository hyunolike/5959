# 화면 완성도 개편과 새 로고

2026-10-13 사용자가 "넥스터즈, 디프만 같은 주요 동아리의 깃허브 저장소를 참고해 디자인을 개편하고, 서비스 로고도 포함하고, 필요한 에셋은 codex로 만들어 달라"고 요청했다. 물어서 정한 것은 셋이다.

- 바꾸려는 것은 **화면 완성도**다. 같은 날 한 개편(#61)의 색과 방향(검정 잉크와 감정 색, 브랜드 색 없음)은 유지한다.
- 로고는 **심볼과 글자를 처음부터 다시** 만든다.
- 진행은 **공용 부품부터**다. 공용 부품과 화면 틀을 먼저 다듬고 로그인, 홈, 글 상세를 손본다. 나머지 화면은 부품을 따라 바뀐다.

시안(화면 다섯 장): https://claude.ai/artifact/1bkhZGnhNnZrijpm4XkLgS. 사용자가 시안을 보고 진행하라고 했다. 기준 main은 `7448324`다.

## 참고한 것과 경계

GitHub의 Nexters, depromeet, YAPP-Github, dnd-side-project, sopt-makers에서 2024~2026년의 웹 저장소 13개를 읽었다. 디자인 시스템 전용 저장소는 없고 토큰과 부품은 서비스 저장소 안에 있다.

| `Nexters/pallang-client`   | Next 16과 Tailwind v4, 댓글과 공감이 있는 커뮤니티에 마스코트. 토큰, 움직임, 하단 메뉴, 시트, 빈 화면 부품 |
| `Nexters/yogieat`          | 색, 모서리, 간격, 그림자, 글자를 파일로 나눈 토큰                                                          |
| `Nexters/PomoNyang-fe`     | 캐릭터를 상태별로 나눠 쓰는 방식                                                                           |

| `depromeet/layer`          | 공용 부품의 구성                                                                                           |

여러 저장소에서 되풀이되는 것만 가져온다.

- 모서리는 8, 12, 16, 24px와 알약이다.
- 누르는 것의 높이는 40, 48, 56px이고 간격은 4px 단위다.
- 그림자는 거의 쓰지 않는다. 떠 있는 것(토스트)에만 쓴다.
- 보조 버튼은 테두리가 아니라 옅은 채움이다.
- 누르면 120ms 동안 0.97배로 줄어든다.
- 빈 화면과 오류는 캐릭터 그림, 한 줄 제목, 설명, 버튼 하나로 맞춘다.
- 시트는 위쪽 모서리가 24px이고 손잡이가 있다.
- 로고는 SVG이고 심볼과 글자를 파일로 나눈다.

**읽은 저장소에는 모두 LICENSE가 없다.** 구조와 규칙만 참고한다. 코드, 캐릭터, 로고, 글꼴 파일은 가져오지 않는다. 그 서비스들이 쓰는 선명한 브랜드 색 하나는 따르지 않는다(색은 유지하기로 했다).

## 목표

1. 공용 부품의 모양 규칙을 위의 값으로 맞추고, 화면은 그 부품만 쓴다.
2. 로그인 첫 화면, 홈, 글 상세에서 첫눈에 보이는 것을 정리한다.
3. 새 로고 한 벌을 만들어 머리말, 앱 아이콘, 파비콘, 공유 이미지에 쓴다.
4. 기능, API, 계약, 주소는 바꾸지 않는다.

## 바꾸지 않는 것

- 색 토큰(잉크, 감정 색, 게임 노랑, 위험과 주의)과 글꼴(Pretendard), 글자 크기 단계.
- 몬스터 그림과 오구 캐릭터 그림. 도감 카드의 반짝임.
- 넓은 화면의 옆 메뉴 구성. 이번 개편은 좁은 화면(390px)을 기준으로 하고 넓은 화면은 깨지지 않게만 본다.
- 접근성 규칙(`docs/DESIGN_SYSTEM.md`의 접근성 절)과 지키는 검사.

## 토큰

정본은 `apps/web/src/core/styles/globals.css`다.

| 이름                | 지금 | 바뀐 뒤                           | 쓰임                                                             |
| ------------------- | ---- | --------------------------------- | ---------------------------------------------------------------- |
| `radius-inline`     | 8px  | 8px                               | 작은 표시                                                        |
| `radius-control-sm` | 없음 | 12px                              | 세그먼트, 40px 높이의 버튼                                       |
| `radius-control`    | 14px | 16px                              | 버튼, 입력, 썸네일                                               |
| `radius-surface`    | 20px | 24px                              | 시트, 무대, 하단 메뉴                                            |
| `shadow-float`      | 없음 | `0 8px 24px rgb(23 23 28 / 0.18)` | 토스트                                                           |
| `shadow-raised`     | 없음 | `0 1px 2px rgb(23 23 28 / 0.08)`  | 세그먼트에서 고른 칸                                             |
| `color-kakao`       | 없음 | `#fee500`                         | 카카오 로그인 버튼의 바탕(카카오 지정 색). 다른 곳에 쓰지 않는다 |

- 누름: `.ogu-pressable`에 `transform: scale(0.97)`을 `--duration-fast`로 더한다. `prefers-reduced-motion`이면 크기를 바꾸지 않는다. 게임 버튼은 지금의 눌림(아래로 내려감)을 유지한다.
- 높이: 작은 것 40px(`h-10`), 기본 48px(`h-12`), 큰 것 56px(`h-14`). 지금의 44px과 52px을 이 세 단계로 옮긴다. 보이는 높이가 40px인 것은 `::before`로 누르는 영역을 44px로 넓힌다.

## 공용 부품

| 부품                          | 바뀌는 것                                                                                                                                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Button`                      | `secondary`를 옅은 채움(`bg-surface-sunken`)으로 바꾼다. 지금의 `subtle`과 같아지므로 `subtle`을 없애고 쓰던 곳을 `secondary`로 옮긴다. 테두리가 꼭 필요한 곳(구글 로그인)에는 `outline`을 둔다. 크기는 `sm` 40, `md` 48, `lg` 56 |
| `Chip`                        | 고르지 않은 것은 옅은 채움, 고른 것은 잉크 채움. 테두리를 없앤다. 높이 40px                                                                                                                                                       |
| `SegmentedControl` (새로)     | 둘이나 셋 가운데 하나를 고른다(정렬). 옅은 바탕 안에서 고른 칸만 흰 면과 `shadow-raised`. `role="group"`과 `aria-pressed`                                                                                                         |
| `Input`, `Textarea`, `Select` | **테두리를 유지한다.** 시안은 채움만 그렸지만, 입력란의 경계는 흰 바탕과 3:1이 넘어야 한다(WCAG 1.4.11). 지금의 `line-strong`(3.4:1) 테두리를 두고 모서리와 높이(56px)만 맞춘다. 초점에서는 테두리가 잉크 2px이 된다              |
| `EmptyState` (새로)           | 그림(132px), 제목, 설명, 버튼 하나. 피드, 알림, 도감, 내 활동, 글 상세의 빈 화면과 오류가 이것을 쓴다. 오류일 때 문구는 `role="alert"`                                                                                            |
| `ConfirmDialog`               | 시트일 때 위쪽 모서리 24px과 손잡이(장식, `aria-hidden`). 버튼 두 개는 같은 너비로 나란히                                                                                                                                         |
| `Toaster`                     | 잉크 바탕의 띠. 하단 메뉴 위에 뜨고 `shadow-float`. 시안에 그린 되돌리기 버튼은 넣지 않는다(되돌릴 동작이 없다)                                                                                                                   |
| `PageHeader` (새로)           | 안쪽 화면의 머리말. 왼쪽 뒤로 가기(44px), 가운데 제목(17px 굵게). 글 상세가 쓴다                                                                                                                      |
| `BrandMark`                   | 새 로고의 가로형 SVG 하나로 바꾼다. 아래 "로고" 참고                                                                                                                                                                              |

부품을 바꾸면 `docs/DESIGN_SYSTEM.md`의 모양과 컴포넌트 표, 디자인 카탈로그(`ENABLE_DESIGN_CATALOG`)를 함께 고친다.

## 화면

### 화면 틀 (`widgets/app-shell`)

- 머리말 높이를 좁은 화면에서 56px로 줄인다.
- 글 상세(`/post/[id]`)에서는 좁은 화면의 하단 메뉴를 숨긴다. 그 자리에 댓글 입력줄이 온다. 넓은 화면의 옆 메뉴는 그대로다.
- 글 상세는 `PageHeader`로 뒤로 가기를 보인다. 지금의 "< 마음 이야기" 글자 링크를 대신한다. 알림, 글쓰기, AI 친구 안내는 큰 제목이 첫 줄 역할을 해서 그대로 둔다.

### 로그인 첫 화면 (`/login`)

- 위에서부터 오구(132px, 옅은 면 위), "오늘 마음은 어때요?", 서비스 두 줄 소개, 감정 이름 다섯(이름이 있는 목록)이다.
- 아래에 카카오로 계속하기(`color-kakao` 바탕), 구글로 계속하기(`outline`), 이메일로 로그인(`secondary`)을 56px 높이로 쌓는다.
- 이메일과 비밀번호 입력란은 "이메일로 로그인"을 누르면 같은 화면에서 펼쳐진다. 펼칠 때 초점을 이메일 칸으로 옮긴다. 이메일로 가입한 계정이라는 안내(`error=email_registered`)와 함께 돌아오면 처음부터 펼쳐 두고 초점은 옮기지 않는다. 로그인에 실패하면 화면이 바뀌지 않아 펼쳐진 채로 오류가 보인다. 다시 접어도 적어 둔 값은 남는다.
- 먼저 둘러보기와 회원가입은 맨 아래에 나란히 둔다.
- 화면의 `h1`은 문서 제목과 같은 "로그인"이고 읽히기만 한다. 보이는 머리 문구 "오늘 마음은 어때요?"는 문단이다. 실제 API e2e 다섯 곳이 `h1` "로그인"으로 이 화면을 알아본다.
- 회원가입 화면(`/signup`)은 입력란이 주인공이라 구성을 그대로 두고 부품만 따라 바뀐다.

### 홈 (`/home`)

- 로그아웃 버튼을 홈에서 뺀다. 기록(`/my`)에 이미 있다.
- 위쪽의 고민 쓰기 버튼은 좁은 화면에서 뺀다. 하단 메뉴 가운데에 같은 것이 있다. 넓은 화면에는 남긴다.
- 정렬은 `SegmentedControl`, 필터 여닫이("필터")는 그 오른쪽에 한 줄로 둔다. 필터를 누르면 지금처럼 그 아래에 칩이 펼쳐지고, 고른 필터가 있으면 개수를 적는다(지금 동작).
- 홈 화면에 추가 안내는 목록 위 한 줄에서 목록 아래로 옮긴다.
- 비회원 홈(011)의 최근 이야기 목록은 같은 글 항목 간격을 쓴다. 구성은 바꾸지 않는다.

### 글 상세 (`/post/[id]`)

- 몬스터 무대의 모서리가 24px이 된다. 무대 안의 배치는 그대로 둔다.
- 댓글 입력을 화면 아래에 고정한다(좁은 화면). 한 줄에서 시작해 네 줄까지 늘어나는 입력란과 등록 버튼이다. 글자 수는 남은 글자가 50자 아래일 때만 보인다. `env(safe-area-inset-bottom)`만큼 띄운다. 넓은 화면에서는 지금 자리(댓글 목록 아래)에 둔다.
- 본문과 댓글 사이는 선 대신 옅은 면의 8px 띠로 나눈다.
- 신고, 수정, 삭제는 지금 자리에 둔다. 시안의 더 보기 버튼은 넣지 않는다. 메뉴 부품을 새로 만들 만큼의 쓰임이 없다.

### 그 밖의 화면

글쓰기, 기록, 도감, 레이드, 알림, 주간 리포트는 구성을 바꾸지 않는다. 부품과 토큰이 바뀌어 모서리, 높이, 버튼의 무게가 따라 바뀐다. 빈 화면과 오류만 `EmptyState`로 옮긴다.

## 로고

새로 만든다. 지금의 오구 얼굴 그림(192px webp)과 #68의 보라색 선 글자를 대신한다.

**조건**

- 주 버전은 잉크(#17171c) 한 색이다. 화면에 브랜드 색을 두지 않기 때문이다. 오구의 잎에만 초록 한 점을 쓸 수 있다.
- 16px에서 읽힌다(파비콘). 심볼의 주요 선은 64 단위 눈금에서 6 이상이다.
- 글자는 글꼴 파일에 기대지 않는 도형이다.
- 보라색은 쓰지 않는다(불안의 색).

**과정**

1. codex가 방향이 다른 후보 셋을 SVG로 만든다: 오구 얼굴을 단순하게 한 것, "오구오구" 글자 자체가 캐릭터가 되는 것, 5959(오구)를 살린 것.
2. 시안 캔버스에 올려 사용자가 하나를 고른다.
3. 고른 것을 다듬어 한 벌을 만든다.

2026-10-13에 사용자가 **얼굴**(둥근 얼굴, 두 눈, 미소, 초록 잎과 둥근 선 글자)을 골랐다. 다듬을 것: "오"의 세로획이 짧아 작게 보면 "으"로 읽힌다. 세로획을 늘리고 심볼과 글자의 굵기를 맞춘다. 눈이 든 "오"(글자 후보)는 돼지 코처럼 보였고, 59는 위로하는 서비스라는 인상이 없었다.

**한 벌**

| 파일 | 쓰임 |
| --- | --- |
| `public/brand/ogu-logo.svg` | 가로형(심볼과 글자, 304×64). `BrandMark`가 쓴다 |
| `public/brand/ogu-logo-symbol.svg` | 심볼. 홈 화면 추가 안내가 쓴다 |
| `scripts/brand/{icon,app-icon,app-icon-maskable,og-image}.svg` | 아이콘과 공유 이미지의 원본. 화면이 직접 쓰지 않는다 |
| `src/app/icon.png`, `public/brand/ogu-logo-v2-apple-touch-180.png` | 파비콘(96px)과 애플 아이콘. 파비콘은 지금처럼 PNG로 둔다 |
| `public/pwa/ogu-logo-v2-{192,512,maskable-512}.png` | 설치 아이콘. 파일 이름의 판을 올려 설치된 기기의 아이콘이 바뀌게 한다 |
| `src/app/opengraph-image.png` | 공유 이미지(1200×630). 로고와 감정 색 다섯 |

PNG는 `scripts/generate-brand-icons.mjs`가 원본 SVG에서 만든다. 공유 이미지의 주소가 절대 경로가 되도록 루트 메타데이터에 서비스 주소(`APP_ORIGIN`)를 `metadataBase`로 둔다.

글자만 있는 파일은 쓰는 곳이 없어 넣지 않았다. 옛 파일(`ogu-wordmark.svg`, `ogu-symbol.webp`, `ogu-lettering-v1-*`, `icon-*.png`, `apple-touch-icon.png`)은 지웠다.

## codex로 만드는 에셋

- 로고 후보 셋과 고른 뒤의 한 벌(SVG).
- 공유 이미지의 구성.
- 오구의 새 포즈는 만들지 않는다. 빈 화면과 오류는 지금의 세 포즈(인사, 듣기, 안기)로 채운다. 포즈가 모자란 곳이 구현 중에 나오면 그때 codex에 맡기고, 몬스터와 같은 굵은 외곽선과 평평한 채색을 지킨다.

codex가 만든 것은 내가 그려진 모습을 확인한 뒤에 넣는다.

## 검사

- 부품마다 단위 테스트를 먼저 쓴다: 변형의 클래스, `aria-pressed`, 누르는 영역 44px, 오류의 `role="alert"`.
- `token-usage.test.ts`와 `tokens.test.ts`가 그대로 통과한다. 새 토큰 쌍(카카오 바탕과 잉크 글자, 옅은 채움과 보조 글자)의 대비를 `tokens.test.ts`에 더한다.
- 로그인 화면이 바뀌므로 로그인 폼에 기대는 e2e(13곳)를 "이메일로 로그인"을 누르는 것으로 고친다.
- 글 상세의 고정 입력줄: 좁은 화면에서 하단 메뉴가 없고, 입력줄이 댓글 목록의 마지막 줄을 가리지 않고, 넓은 화면에서는 옛 자리에 있는지 e2e로 본다.
- 320, 390, 1440px에서 가로로 넘치지 않는지 본다. 390px 화면을 캡처해 눈으로 확인한다.
- 로고: 16, 32, 180, 512px로 그려 확인한다. `brand-icons.spec.ts`와 `manifest.test.ts`를 새 파일 이름에 맞춘다.

## 남는 위험

- 버튼과 칩의 높이가 바뀌어 화면마다 줄바꿈이 달라질 수 있다. PR 1에서 모든 화면을 320px로 훑는다.
- 입력란은 시안과 달리 테두리가 남는다. 접근성 기준을 지키기 위해서다.
- 설치된 기기의 아이콘은 브라우저와 OS가 바꿔 주어야 바뀐다. 바로 바뀐다고 약속할 수 없다.
