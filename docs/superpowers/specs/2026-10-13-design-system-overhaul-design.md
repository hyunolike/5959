# 디자인 시스템 전면 개편

2026-10-13 사용자가 "지금 화면은 AI가 만든 데모 같다. 실제 B2C 서비스를 참고해 디자인 시스템을 다시 세우고 싶다"고 요청했다. 방향 시안 세 가지를 비교한 뒤 "A 잉크와 감정색을 기본으로 하고, 글 상세와 레이드에는 B 스티커의 두툼한 HP 막대와 행동 버튼을 가져온다"는 추천안을 골랐다. 기준 main은 `f10c4e8`이다.

시안: https://claude.ai/artifact/GuV5Efy58w7VnYYP4GXE5z

## 왜 바꾸나

코드에서 확인한 원인이다.

- 글자 크기가 14px 125곳, 12px 58곳에 몰려 있고 16px 이상은 40곳 남짓이다. 화면에 위계가 없다.
- Spoqa 파일은 400과 700뿐인데 `font-medium`과 `font-semibold`를 42곳에서 쓴다.
- 연보라 배경에 보라 버튼과 보라빛 칩을 쓴다. 불안 몬스터도 보라색이라, 보라가 서비스를 뜻하는지 불안을 뜻하는지 구분되지 않는다.
- 통계 차트의 감정 색(`EMOTION_COLORS`)이 몬스터 그림의 색과 다르다.
- 몬스터 그림 30장을 피드에서 40px로 쓴다.
- 토큰이 한 층이라 컴포넌트가 `brand-600` 같은 원색 이름을 직접 쓴다. 회색 300이 400보다 어둡다.
- `DESIGN_SYSTEM.md`의 값이 `globals.css`와 다르다.
- 공용 `Button`을 거치지 않는 `<button>`이 17곳이고, Tailwind 기본 색(`text-red-600` 44곳 등)을 직접 쓴다.

## 목표

1. 색, 글자, 모양, 움직임의 규칙을 역할 이름이 붙은 토큰으로 정하고, 화면은 그 토큰만 쓴다.
2. 피드는 글을 읽기 좋게, 글 상세와 레이드는 몬스터가 주인공이 되게 한다.
3. 기능, API, 계약, 라우트는 바꾸지 않는다.

## 참고와 경계

- 토큰 구조와 글자 단계는 당근 SEED Design과 토스 TDS의 공개 문서를 참고한다. 공개 범위와 라이선스는 구현 계획을 쓸 때 직접 확인한다.
- 피드의 밀도와 글 항목 구성은 블라인드와 당근 동네생활을, 캐릭터를 크게 쓰는 방식은 듀오링고를 참고한다.
- 구조와 규칙만 참고한다. 다른 서비스의 색, 아이콘, 캐릭터, 코드는 가져오지 않는다.

## 토큰

정본은 `apps/web/src/core/styles/globals.css`다. 세 층으로 나눈다.

**원색 층.** 화면에서 직접 쓰지 않는다.

| 이름 | 값 | 쓰임 |
| --- | --- | --- |
| ink-900 | #17171c | 본문, 주요 버튼 |
| ink-800 | #2a2a32 | 댓글 본문 |
| ink-700 | #45454f | 보조 글자 |
| ink-600 | #6b6b76 | 부가 정보, 선택 안 된 메뉴 |
| ink-500 | #8a8a95 | 입력 테두리 (흰 바탕과 3.4:1) |
| ink-300 | #dcdce2 | 옅은 테두리 |
| ink-200 | #ececf0 | 구분선, 막대 바탕 |
| ink-100 | #f5f5f7 | 가라앉은 면 |
| white | #ffffff | 바탕 |
| game-yellow | #ffd60a | 게임 행동 버튼 |
| danger-700 / danger-50 | #b42318 / #fef3f2 | 오류, 삭제 |
| warning-700 / warning-50 | #b54708 / #fffaeb | 숨김 표시, 주의 |

감정 색은 몬스터 그림에서 뽑는다. 감정마다 진한 색, 옅은 색, 글자 색 세 가지다.

| 감정 | 진한 색 | 옅은 색 | 글자 색 |
| --- | --- | --- | --- |
| 불안 | #8b5cf6 | #f1ebff | #5334b8 |
| 무기력 | #7187e0 | #e9edfc | #3346a3 |
| 외로움 | #35b6d3 | #e0f5fa | #0d6379 |
| 자기비하 | #8a9a3c | #f0f3de | #56621d |
| 짜증 | #e5484d | #fdeaea | #a81f26 |

글자 색과 옅은 색의 대비는 다섯 감정 모두 5.8:1 이상으로 측정했다. 시안의 오류 색(#d92d20)은 옅은 바탕에서 4.44:1이라 #b42318로 바꿨다.

**역할 층.** 화면과 컴포넌트가 쓰는 이름이다. `page`, `surface`, `surface-sunken`, `line`, `line-strong`, `fg`, `fg-muted`, `fg-subtle`, `action`, `action-hover`, `on-action`, `focus`, `danger`, `danger-tint`, `on-danger`, `warning`, `warning-tint`, `emotion`, `emotion-tint`, `emotion-fg`, `game`, `game-line`, `scrim`. Tailwind 유틸리티로는 `text-fg`, `bg-surface`, `border-line`처럼 쓴다.

원색 층은 `:root`의 CSS 변수로만 두고 Tailwind 테마에 넣지 않는다. 그래서 `bg-ink-900` 같은 유틸리티는 생기지 않는다.

- `action`은 ink-900이다. 브랜드 색은 두지 않는다. 화면의 색은 감정에서만 나온다.
- `emotion-*`은 `data-emotion` 속성이 붙은 요소 안에서 그 감정의 값으로 바뀐다. 태그, HP 막대, 무대, 차트가 같은 값을 쓴다.
- 감정 색은 감정을 나타낼 때만 쓴다. 오류와 삭제는 `danger`를 쓰고, 짜증의 빨강을 상태 표시에 쓰지 않는다.

**컴포넌트 층.** 버튼 높이, 칩 높이처럼 한 컴포넌트에만 쓰는 값이다. 해당 컴포넌트 파일 안에 둔다.

## 글자

Pretendard 가변 글꼴을 npm 패키지 `pretendard`(1.3.9, SIL OFL 1.1)의 동적 서브셋 CSS로 싣는다. 글자 범위별로 35~45KB 조각을 필요한 만큼만 받고, 파일은 우리 출처에서 나간다. Spoqa 파일은 지운다. 굵기는 400, 500, 700, 800만 쓴다.

| 이름 | 크기 / 줄 높이 | 쓰임 |
| --- | --- | --- |
| caption | 12 / 16 | 감정 태그, HP 숫자 |
| label | 13 / 18 | 작성자 정보, 시각 |
| body-sm | 15 / 24 | 댓글, 입력 |
| body | 16 / 26 | 피드 본문 |
| body-lg | 17 / 29 | 글 상세 본문 |
| title | 20 / 28 | 구역 제목 |
| heading | 24 / 32 | 화면 제목 |
| display | 32 / 40 | 레이드 보스 이름 |
| numeric | 36 / 40 | 레이드 HP |

숫자는 `tabular-nums`로 쓴다. 작성 시각은 "12분 전"처럼 쓰고, 일주일이 지나면 날짜로 쓴다.

## 모양, 간격, 움직임

- 모서리: 8px(작은 요소), 14px(버튼, 입력, 썸네일), 20px(시트, 큰 면), 완전한 둥근 모양(칩, 태그).
- 높이: 칩 36px, 버튼 최소 44px, 입력과 주요 버튼 52px, 게임 버튼 56px. 터치 영역은 44px 이상이다.
- 간격: 4px 단위. 화면 좌우 여백 20px, 구역 사이 24px.
- 테두리와 그림자: 기본은 1px 테두리이고 그림자는 쓰지 않는다. 게임 요소만 2px 먹색 외곽선과 아래로 4px 내려간 단색 그림자를 쓴다.
- 움직임: 시간은 120ms, 200ms, 320ms 세 단계다. 게임 버튼은 누르면 그림자만큼 내려간다. 몬스터의 대기 움직임(ADR-0006)은 그대로 둔다. `prefers-reduced-motion`이면 움직이지 않는다.
- 아이콘: Lucide를 Phosphor(`@phosphor-icons/react` 2.1.10, MIT)로 바꾼다. 기본은 선, 선택된 메뉴와 누른 공감은 채운 모양이다.
- 테마: 라이트 한 가지로 유지한다.

## 게임 요소를 쓰는 곳

두툼한 외곽선과 노란 버튼은 아래에만 쓴다.

- 글 상세의 몬스터 무대: 큰 HP 막대, "공감 보내기" 버튼.
- 레이드: 큰 HP 막대, "공격하기" 버튼.

피드, 글쓰기, 가입과 로그인, 마이페이지, 알림은 차분한 기본 모양만 쓴다. 위기 안내, 숨김 표시, 신고, 재검토 요청에는 게임 요소와 감정 색을 쓰지 않는다(헌법 IV).

## 인수 조건

**US1 토큰**

- DS-US1-AC1: 소스에 옛 토큰 이름(`brand-*`, `neutral-*`, `leaf-*`)과 Tailwind 기본 색 클래스(`red-600`, `white` 등)가 없다. 옮기는 동안에는 아직 안 옮긴 파일 목록을 두고, 목록이 줄기만 하도록 자동 검사가 지킨다.
- DS-US1-AC2: 글자와 바탕으로 함께 쓰는 토큰 쌍의 대비가 4.5:1 이상이다(24px 이상은 3:1). 단위 테스트가 계산한다.
- DS-US1-AC3: 감정 색은 한 곳에서 정의되고 태그, HP 막대, 무대, 차트가 같은 값을 쓴다.
- DS-US1-AC4: 글꼴 굵기는 400, 500, 700, 800만 쓴다.

**US2 컴포넌트**

- DS-US2-AC1: 모든 버튼이 Button, GameButton, IconButton, Chip 가운데 하나다.
- DS-US2-AC2: 누를 수 있는 요소의 영역이 44px 이상이다.
- DS-US2-AC3: `ConfirmDialog`의 기존 history와 초점 복귀 테스트가 그대로 통과한다.
- DS-US2-AC4: 카탈로그 페이지에서 모든 공용 컴포넌트의 변형과 상태를 볼 수 있다.

**US3 화면**

- DS-US3-AC1: 피드 항목에 감정 태그, 상대 시각, 48px 몬스터와 HP가 보인다.
- DS-US3-AC2: 글 상세의 무대가 그 글의 감정 색이고, 큰 HP 막대와 게임 버튼이 있다.
- DS-US3-AC3: 레이드의 무대가 보스의 감정 색이고, HP 숫자와 게임 버튼이 있다.
- DS-US3-AC4: 위기 안내, 숨김 표시, 신고, 재검토 요청에는 게임 요소와 감정 색이 없다.
- DS-US3-AC5: 비회원 홈은 실제 몬스터 그림을 보여 주고, 보호된 API를 부르지 않으며 가짜 글과 수치가 없다.
- DS-US3-AC6: 390px과 1440px에서 가로로 넘치지 않는다.
- DS-US3-AC7: 메뉴에서 지금 있는 곳은 채운 아이콘과 굵은 글씨로, 나머지는 선 아이콘으로 보인다.

**US4 보존**

- DS-US4-AC1: 기존 단위 테스트와 e2e의 동작 기대값이 그대로 통과한다. 바뀌는 것은 선택자와 색, 글꼴 기대값뿐이다.
- DS-US4-AC2: `contracts/`와 `apps/api`에 변경이 없다.
- DS-US4-AC3: `prefers-reduced-motion`에서 움직임이 없다.
- DS-US4-AC4: `DESIGN_SYSTEM.md`의 값이 `globals.css`와 같다.

## 진행 순서

main에 병합하면 운영에 바로 배포된다. 그래서 통합 브랜치 `design/system-v2`를 두고 아래 PR을 차례로 그 브랜치에 넣은 뒤, 마지막에 한 번 main으로 보낸다.

1. 토큰과 글꼴. 옛 토큰 이름은 새 값에 이어 두어 화면이 깨지지 않게 한다.
2. 공용 컴포넌트, 몬스터 컴포넌트, 카탈로그 페이지.
3. 앱 틀과 피드.
4. 글 상세와 댓글.
5. 레이드.
6. 글쓰기, 가입과 로그인, 온보딩.
7. 마이페이지, 통계, 주간 리포트, 알림.
8. 비회원 홈, 옛 토큰과 Lucide 제거, 문서 갱신, 접근성 점검.

PR마다 390px과 1440px 화면 캡처를 붙인다.

## 검증

- 단위: 컴포넌트의 변형과 상태, 토큰 대비 계산, 상대 시각 함수.
- 자동 검사: 화면 코드의 원색 이름과 기본 색 클래스 금지(DS-US1-AC1).
- e2e: 기존 `design-system.spec.ts`의 배경과 글꼴 기대값을 새 값으로 바꾸고, 가로 넘침 검사를 유지한다. 실제 API를 띄운 e2e는 동작 기대값을 바꾸지 않는다.
- 마지막 PR에서 `design:accessibility-review`와 `transitions-polish`로 점검한다.

## 위험

- **불안(보라)과 무기력(남색)의 색이 가깝다.** 차트에서 색만으로는 가르기 어렵다. 차트는 지금처럼 이름과 숫자를 함께 쓰고, 두 색의 밝기 차이를 구현 때 벌린다.
- **노란 게임 버튼이 유일한 채색 버튼이다.** 글 상세와 레이드 밖으로 번지면 규칙이 무너진다. GameButton을 쓰는 곳을 자동 검사로 묶을지 구현 계획에서 정한다.
- **e2e 선택자가 많이 바뀐다.** 화면 PR마다 해당 화면의 e2e를 같이 고친다.
- **입력 테두리를 시안보다 진하게 했다.** 시안의 #dcdce2는 흰 바탕과 1.4:1이라 입력 칸의 경계가 기준(3:1)에 못 미친다. #8a8a95로 정했다.
