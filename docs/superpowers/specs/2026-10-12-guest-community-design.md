# 익명 둘러보기와 커뮤니티 흐름

2026-10-12 사용자가 로그인 화면의 먼저 둘러보기, 익명 홈의 contextual 로그인 안내, 실제 B2C 패턴에 따른 전체 화면 고도화를 요청했다. 로컬 구현·검증·커밋만 승인했으며 push/PR/merge/deploy는 하지 않는다. 기준 main은 `5e1929e`다.

## 데이터 결정

`SecurityPaths.PUBLIC`에는 피드·게시글 상세·내 프로필이 없다. 기존 feed/detail API 테스트는 익명 조회 401을 요구한다. 공개 데이터 API나 공개 동의 필드는 없으므로 이번 변경은 회원 글/개인정보를 공개하지 않는다. 정확한 `/home` 페이지에만 익명 서비스 안내와 실제 메뉴 구조를 열고, 개인 API를 요청하는 피드·보스·알림·프로필 컴포넌트를 익명 화면에서 렌더링하지 않는다. 가짜 게시글·지표·회원 수를 추가하지 않는다.

## 이번 커밋의 인수 조건

- GUEST-US1-AC1: 로그인 화면에 `/home` 먼저 둘러보기 링크. 익명 홈 직접 접근과 새로고침 가능; 온보딩 전 회원의 기존 guard는 유지.
- GUEST-US1-AC2: 익명 홈의 글쓰기·레이드·내 기록 선택은 동일한 로그인 sheet. 취소/Escape/배경/뒤로 가기는 홈 유지와 트리거 초점 복귀. 빠른 반복 클릭은 중복 안내/즉시 닫기/이동을 만들지 않음.
- GUEST-US1-AC3: 로그인 확인은 `sanitizeNextPath`/기존 로그인·OAuth·온보딩 return-to-intent를 이용. 외부 next 차단. 안내 history entry를 로그인으로 교체하여 뒤로/앞으로 때 닫힌 안내가 재등장하지 않음. 상세·개인 메뉴 직접 URL은 기존 로그인 redirect.
- GUEST-US1-AC4: 익명 홈은 보호 API 요청/회원 정보/회원 글을 표시하지 않음. 실 API의 익명 조회·글쓰기·공감·댓글 401, 세션 만료 및 재탐색을 검증. 실제 로그인 회원의 피드·작성·상세·개인 기록 흐름 보존.


## 전체 B2C 디자인 방향 — 로그인 후 Claude Code 실제 구현을 통합

| 화면 | 첫 정보와 다음 행동 | 변경 이유 |
|---|---|---|
| 익명 홈 | 어떤 공간인지, 글은 로그인 후 조회, 글쓰기/메뉴 탐색 | 노출 범위를 정직하게 설명하면서 강제 로그인 이전의 탐색 제공 |
| 로그인·가입 | 같은 폭의 간결한 폼, 가입/로그인 전환과 둘러보기 | 가입만 좁은 장식 카드였던 불일치 제거 |
| 회원 피드 | 실제 고민 미리보기와 작성, 정렬·필터 | 로그아웃·캐릭터 장식을 주 콘텐츠보다 강조하지 않음 |
| 작성 | 자유 입력, 듣고 싶은 댓글 말투, 공개 범위, 올리기 | 장식 아이콘 대신 결정에 필요한 설명에 집중; 임시저장 기능을 꾸미지 않음 |
| 상세 | 본문과 작성자, 공감/댓글, 감정 표현, 댓글 | 몬스터를 본문 앞에 두던 계층 역전 해소 |
| 내 정보·설정 | 내 마음 기록, 프로필 정보·수정, 감정 통계·활동 | 기존 `/my/edit` 프로필 설정만 제공; 없는 독립 설정 기능 추가 안 함 |
| 빈 상태·오류·로딩 | 상황 설명과 가능한 실제 다음 행동 | 목록/작성으로 실제 이동, 기존 접근성과 스켈레톤 유지 |
| 공통 탐색 | 동일한 PC/모바일 메뉴와 현재 위치 | 익명은 참여 안내, 회원은 기존 이동; 알림 스트림은 회원에게만 |

최종 통합본은 기존 디자인 토큰, Spoqa 폰트, 오구+5959 브랜드를 유지한다. 흰 읽기 면과 중립 hover, 기존 보라 CTA 및 연보라 선택 상태를 이용한다. 주 행동과 선택 상태를 구분하고, 글 본문을 몬스터와 반응보다 먼저 배치한다. 신규 로고·캐릭터·의존성을 추가하지 않았다.

## 참고한 패턴과 한계

- [보투게더 guest E2E](https://github.com/woowacourse-teams/2023-votogether/blob/dev/frontend/cypress/e2e/guestFeatureTest.cy.ts), [PrivateRoute](https://github.com/woowacourse-teams/2023-votogether/blob/dev/frontend/src/routes/PrivateRoute.tsx): 탐색과 참여 권한을 구분. 오구에는 공개 글 API가 없어 동일한 공개 범위를 도입하지 않고 실제 alert도 복제하지 않음.
- [리뷰미](https://github.com/woowacourse-teams/2024-review-me): 부모의 실제 README 이미지 검토에서 전달된 짧은 미리보기·본문/응답 계층을 참고. 평가 설문/날짜 UI/이미지/코드 복제 안 함.
- [Layer](https://github.com/depromeet/layer): 작성 중 한 과제에 집중하는 흐름을 참고. 자유 작성 유지; 없는 저장/추천 API 도입 안 함.
- [GAMSS](https://github.com/Nexters/GAMSS-Android): 감정 기록에 캐릭터를 맥락적으로 사용한다는 제품 설명만 참고. 실제 시각 화면은 확인하지 않아 디자인 근거로 주장하지 않음.
- [Discourse 사용자 안내](https://meta.discourse.org/t/understanding-discourse-for-new-users/96331): 목록→본문→답글/반응과 접근 권한을 분리하는 기본 동선 참고.

외부 프로젝트 코드를 가져오거나 이미지·캐릭터를 복제하지 않았다. 첨부 Library PNG는 공식 materialization helper 다운로드가 실패해 확인하지 못했다.

Claude Code 공식 CLI `2.1.296`은 처음 loggedIn=false여서 중단했다. 사용자 로그인 완료 후 loggedIn=true를 확인하고 공식 CLI를 실제 실행했다. 필요한 UI 소스34개와 기존 오구 PNG만 제한된 staging에 전달했다. safe/restricted 모드, 파일 도구만 허용, MCP/명령/세션 저장 비활성화; 인증 provider/공용 확인창/브랜드 에셋은 쓰기 금지. 자격증명·환경변수·API/서버 소스·실제 회원 데이터·전체 저장소는 전달하지 않았다. UI22개 수정과 화면별 변경 보고를 받았다. CLI는 렌더/타입/린트/기능 테스트를 실행하지 않았고 코디네이터가 검증한다. Superdesign preflight는 기존 인증 확인까지만 수행했으며 비공개 소스 업로드/생성/결제를 하지 않았다.

처음 구현한 익명 범위와 자체 B2C 초안은 충돌 방지를 위해 snapshot/patch로 보존했다. 자체 전체 UI 초안은 되돌린 뒤 Claude Code가 실제 작성한 UI22개만 hash 비교 후 통합했다. 공용 디자인 토큰은 기존 값 유지; 본문/반응 계층, 폼 설명, 잠긴 메뉴 안내와 상태 표현을 개선한다. 별도 pending 작업 대신 최종 렌더/검증/코드리뷰 후 로컬 커밋으로 전달한다.

UX-US2-AC1: 프로필 조회 실패는 끝없는 로딩 대신 오류 안내; 삭제된 글은 실제 목록으로 돌아갈 링크를 제공. 통합 전 기존 코드에서 실패를 확인하는 테스트를 먼저 실행했다.
