# ADR-0006 AI로 그린 캐릭터 그림으로 몬스터를 바꾼다

- 상태: 채택 (ADR-0003을 대체)
- 날짜: 2026-10-10

## 맥락

ADR-0003은 React Three Fiber로 몬스터를 코드로 만들기로 했다. 그림을 따로 그리지 않아도 되고 저작권 문제가 없다는 것이 까닭이었다. M7까지 만들고 보니 결과물은 공에 눈과 입을 붙인 도형이었다. 감정마다 형태와 색은 달랐지만 캐릭터라고 부르기 어려웠고, 서비스가 말하려는 "내 고민이 몬스터가 된다"가 화면에서 전해지지 않았다. ADR-0003도 "아트 완성도는 전문 디자이너의 그림에 못 미친다"고 적어 두었다.

그사이 이미지 생성 도구로 한 화풍의 캐릭터를 여러 장 맞춰 그릴 수 있게 됐다. ADR-0003이 AI 생성을 물리친 까닭("5종의 스타일을 맞추기 어렵다")은, 먼저 그린 그림을 참고로 넘겨 다음 그림을 그리게 하는 방식으로 풀렸다.

## 결정

몬스터를 그린 캐릭터 그림으로 바꾸고 코드 생성 3D를 걷어 낸다.

- 감정 5종 × HP 단계 4개(멀쩡함, 상처 입음, 약해짐, 쓰러짐) 20장과, 레이드 보스 5종의 살아 있는 모습과 쓰러진 모습 10장을 둔다. 모두 `apps/web/public/monsters/`의 투명 배경 512×512 WebP다.
- 그림은 Codex CLI의 이미지 생성으로 만들었다. 불안 몬스터 한 장을 먼저 그려 화풍을 정하고, 그 그림을 참고로 넘겨 나머지 감정을 그렸다. 단계별 그림과 보스는 그 감정의 기본 그림을 참고로 넘겨 같은 캐릭터로 보이게 했다.
- 피드, 글 상세, 레이드가 모두 같은 그림을 쓴다. 상세와 레이드에서는 감정마다 다른 CSS 대기 움직임(떨림, 축 처짐, 좌우 흔들림, 끄덕임, 움찔거림)을 준다. 움직임 줄이기가 켜져 있으면 움직이지 않는다.
- 보스는 살아 있는 동안 한 장을 쓰고, HP가 줄어든 것은 색을 빼서 보인다.
- `three`, `@react-three/fiber`, `@react-three/drei`와 3D 장면, 외형 계산, 캡처 스크립트를 지운다.

## 검토한 대안

- **3D를 다듬는다**: 형태와 표정을 더 손볼 수 있지만 도형을 조합하는 방식의 한계가 있다. 든 시간에 견줘 나아지는 폭이 작다.
- **피드만 그림으로, 상세는 3D 그대로**: 피드에서 본 캐릭터와 상세의 도형이 다르게 생겨 같은 몬스터로 보이지 않는다.
- **glTF 모델을 만든다**: 3D의 움직임은 살지만 모델을 만들 수단이 없다.

## 결과

- 캐릭터가 감정을 표정과 몸짓으로 드러낸다.
- Three.js가 빠져 글 상세가 가벼워진다. WebGL 지원 여부, 3D 실패 시 대체, 청크 로딩 실패 같은 경로가 없어진다.
- ADR-0003이 얻었던 것 하나를 잃는다. 상태가 늘면 그림을 새로 만들어야 한다. HP에 따라 연속으로 변하지 않고 네 단계로만 바뀐다.
- 그림은 생성 도구가 만든 것이라 같은 그림을 다시 얻을 수 없다. 원본(1024×1024 PNG)은 저장소에 두지 않았다. 다시 그리려면 남아 있는 그림을 참고로 넘긴다.
- 003의 US5-AC4("입체 그래픽을 지원하지 않는 기기에서는 정지 이미지로")는 지킬 것이 없어졌다. 모든 기기가 같은 그림을 본다. US5-AC2의 "금 간 정도"는 반창고와 표정 같은 그림의 표현으로 바뀌었다.
