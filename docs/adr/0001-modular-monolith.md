# ADR-0001 모듈러 모놀리스

- 상태: 채택
- 날짜: 2026-09-24

## 맥락

오구오구는 글 작성 하나에 감정 분석, 위험 감지, 임베딩 생성, 알림이 연쇄적으로 붙는다.
기능끼리 결합이 강해지기 쉬운 구조이지만, 운영자는 한 명이고 트래픽도 크지 않다.
원본(`webbb-be`)은 레이어 규칙을 문서로만 정해 두었고, 서비스가 다른 도메인의 리포지토리를 직접 부르는 곳이 생겼다.

## 결정

Spring Modulith 기반 모듈러 모놀리스로 만든다.

- 모듈은 파사드 인터페이스(동기)와 도메인 이벤트(비동기)로만 통신한다.
- 모듈 경계와 순환 의존은 `ApplicationModules.verify()`가 테스트에서 검사한다.
- 이벤트는 Event Publication Registry에 기록해 실패하면 재처리한다.

## 검토한 대안

- **마이크로서비스와 Kafka**: 서비스마다 배포, DB, 모니터링이 따로 필요해서 혼자 운영하기에 비용이 크다. 트래픽이 없는 상태에서 분리할 근거도 약하다.
- **별도 AI 워커(Python)**: Spring AI로 충분히 처리할 수 있는 일이고, 언어가 세 가지로 늘어난다.

## 결과

- 배포 단위는 하나지만 모듈 경계는 테스트로 보장된다.
- 나중에 특정 모듈(예: `ai`, `report`)을 분리해야 하면, `spring-modulith-events-kafka`로 이벤트를 외부로 내보내는 방식으로 옮길 수 있다.
- 한 DB를 공유하므로, 다른 모듈의 테이블을 조인하지 않는다는 규칙은 코드 리뷰로 지켜야 한다.
