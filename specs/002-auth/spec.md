# Feature Specification: 인증과 회원

**Feature Branch**: `002-auth`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: "M1 인증과 회원. 오구오구 사용자가 이메일로 가입하고 로그인하거나 카카오, 구글 계정으로 로그인하고, 처음 가입하면 온보딩(닉네임, 직군, 경력)을 마친 뒤 서비스를 쓴다. 로그아웃과 세션 유지(토큰 만료 시 자동 갱신)가 된다. 보호된 화면은 로그인하지 않으면 로그인 화면으로 보낸다. 원본(webbb-be, webbb-fe)의 인증 기능과 온보딩 항목을 참고하고, docs/architecture/overview.md와 docs/adr/0002-bff-auth.md를 따른다. 프론트엔드 오류 수집도 이 마일스톤에서 추가한다. 비밀번호 찾기, 네이버 로그인, 회원 탈퇴는 범위 밖."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 이메일로 가입하고 온보딩을 마친다 (Priority: P1)

처음 온 방문자가 이메일과 비밀번호로 가입하고, 닉네임과 직군, 경력을 입력한 뒤 서비스 첫 화면(홈)에 들어간다.

**Why this priority**: 계정이 있어야 이후의 모든 기능(고민 작성, 댓글, 공감)을 쓸 수 있다. 외부 계정 연동 없이도 혼자 동작하는 가장 작은 가입 경로다.

**Independent Test**: 새 이메일로 가입부터 온보딩 완료까지 진행해 홈에 도착하고, 브라우저를 닫았다 다시 열어도 로그인 상태가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **US1-AC1** **Given** 가입하지 않은 이메일일 때, **When** 규칙에 맞는 비밀번호로 가입하면, **Then** 계정이 만들어지고 로그인된 상태로 온보딩 화면으로 이동한다.
2. **US1-AC2** **Given** 이미 가입된 이메일일 때, **When** 같은 이메일로 가입하면, **Then** 가입되지 않고 "이미 가입된 이메일"이라는 안내를 받는다.
3. **US1-AC3** **Given** 비밀번호가 8자 미만이거나 영문과 숫자를 함께 포함하지 않을 때, **When** 가입하면, **Then** 가입되지 않고 비밀번호 규칙을 안내받는다.
4. **US1-AC4** **Given** 온보딩 화면일 때, **When** 규칙에 맞는 닉네임, 직군, 경력을 입력하고 완료하면, **Then** 프로필이 저장되고 홈으로 이동한다.
5. **US1-AC5** **Given** 다른 사용자가 이미 쓰는 닉네임일 때, **When** 온보딩에서 그 닉네임을 입력하면, **Then** 완료 전에 중복 안내를 받고 저장되지 않는다.
6. **US1-AC6** **Given** 온보딩을 마치지 않은 사용자일 때, **When** 홈이나 다른 보호된 화면으로 이동하면, **Then** 온보딩 화면으로 돌아온다.

---

### User Story 2 - 이메일로 로그인하고 로그아웃한다 (Priority: P1)

가입한 사용자가 이메일과 비밀번호로 로그인하고, 쓰기를 마치면 로그아웃한다.

**Why this priority**: 가입만 있고 로그인이 없으면 두 번째 방문부터 서비스를 쓸 수 없다.

**Independent Test**: US1로 만든 계정으로 로그아웃한 뒤 다시 로그인해 홈에 도착하는지 확인한다.

**Acceptance Scenarios**:

1. **US2-AC1** **Given** 가입과 온보딩을 마친 사용자일 때, **When** 올바른 이메일과 비밀번호로 로그인하면, **Then** 홈으로 이동한다.
2. **US2-AC2** **Given** 비밀번호가 틀렸거나 가입되지 않은 이메일일 때, **When** 로그인하면, **Then** 둘 중 어느 쪽이 틀렸는지 구분하지 않는 같은 안내를 받는다.
3. **US2-AC3** **Given** 같은 계정으로 15분 안에 로그인을 5번 연속 실패했을 때, **When** 다시 로그인하면, **Then** 비밀번호가 맞아도 15분 동안 로그인이 막히고 기다려야 한다는 안내를 받는다.
4. **US2-AC4** **Given** 로그인한 사용자일 때, **When** 로그아웃하면, **Then** 로그인 화면으로 이동하고, 로그아웃 전의 세션으로는 더 이상 보호된 기능을 쓸 수 없다.

---

### User Story 3 - 카카오나 구글 계정으로 시작한다 (Priority: P2)

방문자가 비밀번호를 만들지 않고 카카오나 구글 계정으로 가입하고 로그인한다. 처음이면 온보딩을 거친다.

**Why this priority**: 가입 과정을 줄여 첫 방문자의 이탈을 줄인다. 이메일 가입(US1)만으로도 서비스는 동작하므로 P2로 둔다.

**Independent Test**: 카카오 계정으로 처음 로그인해 온보딩을 거쳐 홈에 도착하고, 로그아웃 후 다시 카카오로 로그인하면 온보딩 없이 홈으로 가는지 확인한다. 구글도 같은 방법으로 확인한다.

**Acceptance Scenarios**:

1. **US3-AC1** **Given** 처음 쓰는 카카오 또는 구글 계정일 때, **When** 그 계정으로 로그인을 마치면, **Then** 새 회원이 만들어지고 온보딩 화면으로 이동한다.
2. **US3-AC2** **Given** 이미 온보딩까지 마친 카카오 또는 구글 계정일 때, **When** 다시 로그인하면, **Then** 온보딩 없이 홈으로 이동한다.
3. **US3-AC3** **Given** 외부 계정의 이메일이 이미 이메일 가입으로 쓰이고 있을 때, **When** 그 외부 계정으로 로그인하면, **Then** 두 계정을 자동으로 합치지 않고, 원래 가입한 방법으로 로그인하라는 안내를 받는다.
4. **US3-AC4** **Given** 외부 로그인 화면에서 사용자가 동의를 취소했을 때, **When** 서비스로 돌아오면, **Then** 로그인 화면에서 다시 시도할 수 있고 오류 화면이 보이지 않는다.

---

### User Story 4 - 로그인 상태가 끊기지 않고, 보호된 화면은 막힌다 (Priority: P2)

로그인한 사용자는 서비스를 쓰는 동안 갑자기 로그아웃되지 않는다. 로그인하지 않은 방문자가 보호된 화면에 들어가면 로그인 화면으로 이동하고, 로그인을 마치면 원래 가려던 화면으로 돌아간다.

**Why this priority**: 글을 쓰다가 세션이 끊겨 내용을 잃으면 사용자 신뢰를 잃는다. 다만 US1과 US2가 있어야 의미가 있다.

**Independent Test**: 로그인 후 짧은 인증 유효 시간이 지나도록 기다렸다가 보호된 화면을 다시 불러와도 로그인 상태가 유지되는지 확인한다. 로그아웃 상태에서 보호된 화면 주소로 바로 들어가 로그인 화면으로 이동하고, 로그인 후 원래 주소로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **US4-AC1** **Given** 로그인한 뒤 짧은 인증 유효 시간이 지났을 때, **When** 보호된 기능을 쓰면, **Then** 다시 로그인하라는 요청 없이 그대로 동작한다.
2. **US4-AC2** **Given** 마지막 활동 뒤 14일이 지났을 때, **When** 서비스에 들어오면, **Then** 로그인 화면으로 이동한다.
3. **US4-AC3** **Given** 로그인하지 않은 방문자일 때, **When** 보호된 화면 주소로 바로 들어가면, **Then** 화면 내용이 보이기 전에 로그인 화면으로 이동한다.
4. **US4-AC4** **Given** US4-AC3으로 로그인 화면에 온 방문자일 때, **When** 로그인을 마치면, **Then** 원래 가려던 화면으로 돌아간다.
5. **US4-AC5** **Given** 로그인한 사용자일 때, **When** 페이지의 스크립트가 인증 정보를 읽으려 하면, **Then** 읽을 수 없다.

---

### User Story 5 - 운영자가 화면 오류를 수집한다 (Priority: P3)

사용자 화면에서 예상하지 못한 오류가 나면 운영자가 그 오류와 발생 화면을 확인할 수 있다.

**Why this priority**: 실제 사용자가 들어오기 시작하는 첫 마일스톤이라 화면 오류를 놓치지 않아야 한다. 기능 자체와는 독립적이다.

**Independent Test**: 운영 환경에서 일부러 오류를 발생시키는 확인용 동작을 실행하고, 오류 수집 화면에 그 오류가 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **US5-AC1** **Given** 운영 환경일 때, **When** 화면에서 처리되지 않은 오류가 나면, **Then** 몇 분 안에 오류 수집 화면에 오류 내용과 발생 화면 주소가 나타난다. (수동 검증)
2. **US5-AC2** **Given** 수집된 오류 기록일 때, **When** 운영자가 내용을 보면, **Then** 비밀번호나 인증 정보 같은 민감한 값은 들어 있지 않다.

---

### Edge Cases

- 가입 도중 같은 이메일로 두 요청이 거의 동시에 들어오면 한 계정만 만들어진다.
- 온보딩에서 두 사용자가 같은 닉네임을 동시에 저장하면 한 명만 성공하고, 다른 한 명은 중복 안내를 받는다.
- 여러 탭에서 동시에 인증 유효 시간이 끝나도, 사용자는 로그아웃되지 않는다.
- 로그아웃한 뒤 브라우저의 뒤로 가기로 보호된 화면에 돌아가도 이전 사용자의 데이터가 보이지 않는다.
- 외부 로그인 서비스가 응답하지 않으면 사용자는 오류 안내를 받고 이메일 로그인으로 진행할 수 있다.
- 카카오 계정이 이메일을 제공하지 않아도 가입할 수 있다.
- 로그인 후 돌아갈 주소가 서비스 밖을 가리키면 따라가지 않고 홈으로 이동한다.
- 닉네임 앞뒤 공백은 저장하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 방문자는 이메일과 비밀번호로 가입할 수 있어야 한다. 이메일은 형식이 올바르고 서비스 안에서 유일해야 한다.
- **FR-002**: 비밀번호는 8자 이상 20자 이하이고 영문과 숫자를 모두 포함해야 한다. 비밀번호는 원문으로 저장하지 않는다.
- **FR-003**: 가입한 사용자는 이메일과 비밀번호로 로그인할 수 있어야 한다. 실패 안내는 이메일과 비밀번호 중 어느 쪽이 틀렸는지 드러내지 않는다.
- **FR-004**: 같은 계정에 15분 안에 로그인이 5번 연속 실패하면, 그 계정의 로그인을 15분 동안 막는다.
- **FR-005**: 방문자는 카카오 또는 구글 계정으로 가입하고 로그인할 수 있어야 한다. 외부 계정은 해당 서비스가 주는 고유 식별자로 구분한다.
- **FR-006**: 외부 계정의 이메일이 기존 이메일 가입 계정과 같아도 계정을 자동으로 합치지 않는다. 원래 가입 방법으로 로그인하라고 안내한다.
- **FR-007**: 새로 가입한 모든 사용자(이메일, 외부 계정)는 닉네임, 직군, 경력을 입력하는 온보딩을 마쳐야 서비스 기능을 쓸 수 있다.
- **FR-008**: 닉네임은 앞뒤 공백을 뺀 1자 이상 10자 이하이며 서비스 안에서 유일해야 한다. 온보딩 화면은 저장 전에 중복 여부를 알려 준다.
- **FR-009**: 직군은 기획, 디자인, 개발, 마케팅, 영업, 인사, 총무, 생산, 회계, 기타 중 하나다. 경력은 신입, 1년차부터 6년차, 7년차 이상 중 하나다.
- **FR-010**: 로그인 상태는 사용자가 활동하는 동안 끊기지 않고 유지되며, 마지막 활동 뒤 14일이 지나면 끝난다.
- **FR-011**: 사용자가 로그아웃하면 그 세션은 서버에서도 무효가 되어 다시 쓸 수 없다.
- **FR-012**: 인증 정보는 페이지의 스크립트가 읽을 수 없는 방식으로만 브라우저에 보관한다. 브라우저는 서비스와 같은 출처의 주소로만 요청한다.
- **FR-013**: 로그인하지 않은 방문자가 보호된 화면에 들어가면 화면 내용이 보이기 전에 로그인 화면으로 보낸다. 로그인 후에는 원래 가려던 서비스 안의 화면으로 돌려보낸다.
- **FR-014**: 보호된 화면은 홈, 글쓰기, 마이페이지, 설정, 온보딩이다. 첫 화면(소개)과 로그인, 가입 화면은 누구나 볼 수 있다. 로그인한 사용자가 첫 화면에 오면 홈으로 보낸다.
- **FR-015**: 로그인한 사용자는 자신의 닉네임, 직군, 경력을 볼 수 있다.
- **FR-016**: 운영 환경의 화면 오류는 오류 수집 서비스로 보내고, 보낼 때 비밀번호와 인증 정보를 제외한다.

### Key Entities

- **회원**: 서비스 사용자. 가입 방법(이메일, 카카오, 구글), 이메일(외부 계정은 없을 수 있음), 닉네임, 직군, 경력, 온보딩 완료 여부, 가입 시각을 가진다.
- **외부 계정 연결**: 회원과 외부 로그인 서비스 계정의 연결. 서비스 종류와 그 서비스의 고유 식별자로 구분하며, 한 외부 계정은 한 회원에게만 연결된다.
- **세션**: 한 기기에서의 로그인 상태. 회원, 발급 시각, 마지막 갱신 시각, 만료 시각, 무효 여부를 가진다. 로그아웃하면 무효가 된다.
- **로그인 시도 기록**: 계정별 최근 로그인 실패 횟수와 시각. 잠금 판단에 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 방문자가 이메일 가입부터 온보딩 완료까지 2분 안에 마친다.
- **SC-002**: 활동 중인 사용자가 14일 동안 다시 로그인하라는 요청을 한 번도 받지 않는다.
- **SC-003**: 보호된 화면 주소 전체에 대해, 로그인하지 않은 방문자가 보호된 내용을 한 번도 보지 못한다.
- **SC-004**: 로그아웃한 세션으로 보호된 기능을 요청하면 100% 거부된다.
- **SC-005**: 화면에서 난 오류가 5분 안에 운영자에게 보인다.
- **SC-006**: 이 마일스톤으로 추가되는 월 인프라 비용이 0원이다.

## Assumptions

- 비밀번호 규칙, 닉네임 규칙, 직군과 경력 목록은 원본(DDD 13기 WEBBB)의 규칙을 그대로 따른다.
- 로그인 유지 기간 14일과 짧은 인증 유효 시간(원본은 15분)은 원본 값을 따른다.
- 로그인 실패 잠금(15분 안에 5번 실패하면 15분 잠금)은 원본에 없던 기본 보안 장치로, 업계 통상 수준을 기본값으로 정했다.
- 외부 계정과 이메일 계정의 자동 병합은 계정 탈취 위험이 있어 하지 않는다. 원본은 연결을 요구했지만, 연결 기능은 이 마일스톤 범위 밖이다.
- 비밀번호 찾기, 네이버 로그인, 회원 탈퇴, 프로필 수정 화면은 범위 밖이다. 원본의 알림용 이메일 발송 기능도 쓰지 않는다.
- 오류 수집 서비스는 무료 요금제 안에서 쓴다.
- 카카오와 구글 개발자 앱 등록, 운영용 키 발급은 저장소 소유자가 직접 한다.
- M0에서 만든 배포 경로와 운영 인프라를 그대로 쓴다.
